# Report Generator — Backend Architecture

Generated by /architecture-map on 2026-08-18 — traced from code, not docs.

This is a Next.js app. Entry points are `app/api/**/route.ts` route handlers, reached from
the browser UI (`/`, `/dashboard`, `/proposal`, `/login`) or, for three routes, called
directly by an external Python script using a shared internal API key. There is no
`vercel.json` / cron config in this repo — every route is invoked on demand, not scheduled.

## Orphaned code (not reachable from any entry point)

Traced but excluded from the diagram above because nothing imports into this cluster from
any route, page, component, or script in the repo:

- `src/lib/workflow-engine.ts` — imports `workbook-hydrator`, `reconciliation-engine`,
  `recalc-engine`, `pivot-engine`, `source-classifier`
- `src/lib/workbook-hydrator.ts` — imports `recalc-engine`, `pivot-engine`,
  `reconciliation-engine`
- `src/lib/recalc-engine.ts`, `src/lib/pivot-engine.ts`, `src/lib/reconciliation-engine.ts`,
  `src/lib/source-classifier.ts`, `src/lib/validation-engine.ts`

These six files form a self-contained cluster that only reference each other — no route,
page, component, or `scripts/*.js` file imports `workflow-engine` (the cluster's apparent
entry point) or any other file in it. It reads as a more sophisticated hydration/recalc/
pivot/reconciliation pipeline than what `excel-dashboard-generator.ts` (the function actually
wired to `POST /api/generate-dashboard`) does — possibly a WIP replacement that was never
switched over.

## Mismatches found

- `GET /api/auth/callback` still exists but its own comment says "OAuth callback no longer
  used — password auth only" and it just redirects to `/login`. Dead route kept in place.
- `GET /api/onboarding-pdf` has no auth check of any kind (not session cookie, not internal
  key) — it's reachable by anyone who hits the URL, unlike every other route in the app.
  `middleware.ts`'s allowlist doesn't exempt it, but the route itself never calls
  `verifySessionToken`, so middleware is what's actually gating it, not the route.
- The dashboard-generation route (`generate-dashboard`) uses the simpler, directly-wired
  `excel-dashboard-generator.ts`, not the more elaborate orphaned
  `workflow-engine.ts` → `workbook-hydrator.ts` pipeline described above — worth confirming
  with Max whether that pipeline is still intended to replace the current generator or should
  be deleted.
